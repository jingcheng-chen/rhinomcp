A

Make improvement dependable

  1. Done

    Give each role a fresh start

    Codex modeler, planner and builder sessions use saved artifacts, scoped tools and budgets. A new conversation can resume from the repository.

    Role and harness map ↗
  2. Done

    Trust measurements, not agent claims

    Saved Rhino models are checked against fixed geometry rules. Deliberately wrong models verify that the evaluator can say no.

    Geometry evidence ↗
  3. Done · supervised replay

    Repair a real capture defect

    A bounded builder generated a patch and revised it after review. The trial passed; the supervisor restored the prior binary. The replay patch was not promoted.

    Builder pilot evidence ↗
    What this result does and does not establish

    This replay used a known defect and supervisor-provided API clues. It demonstrates controlled code repair, not independent discovery or a held-out improvement. Latest recorded root suite: 348 Python tests passed.

  4. Done · supervised desktop

    Reject regressions and recover in Rhino

    Baseline 43/43 → faulty candidate 34/43 → restored baseline 43/43. Recovery survived an interruption at its idle handoff without repeating installation. No candidate was promoted.

    Live recovery evidence and runbook ↗
  5. Engineering still ahead

    Protect the judge & prove generalization

    Isolate evaluation from candidate code, add unseen cases and preserve old capabilities. Then automate acceptance and installation.

    Remaining session infrastructure

    Claude Code adapter, explicit model/version configuration and automatic resume are still planned. Current measurements run inside the candidate's Rhino process; file restrictions alone do not isolate the judge.

B

Learn from a complex benchmark

  1. Done

    Construct exact simple solids

    Box → positioned triangular prism → block with a through-hole. Tests cover size, pose, solid validity and internal geometry.

    Modeling evidence ↗
  2. Done · constrained images

    Read dimensions from three drawings

    Two cuboids were reconstructed from calibrated Top / Front / Right images. Swapping width and depth changes the answer despite equal volume.

    Image reconstruction evidence ↗
    Why this is still far from the chair

    The images are generated orthographic drawings with a known grid, origin, box shape and alignment. Arbitrary perspective screenshots, curves, cushions and hidden geometry have not been demonstrated.

  3. Done · diagnostic only

    Establish the first complex baseline

    Four screenshots → 65 valid named parts. Structure checks pass, but cushions and frame remain schematic. Visual acceptance is unscored; no plugin repair was justified yet.

    See the baseline findings ↗
  4. Next · reusable experiments

    Test curved strips and continuous cushions

    Isolate strip orientation and solid closure, then rounded 2×2 cushion shaping. Decide whether failures need better guidance or a generic tool improvement. Retest across the suite.

  5. One major benchmark

    Reconstruct the complete chair

    Combine the parts into an editable Rhino model using only the input screenshots. Retest on unseen views and preserve the simpler tasks.

    Possible extension

    The linked scene also includes an ottoman. Working scope is chair first; ottoman follows if the full set is desired. Surface materials and photoreal rendering can be a separate fidelity stage.

What will “the chair works” mean?

Proposed acceptance contract · not implemented yet

01 / Looks right

Matches across views

Compare silhouettes and agreed landmarks under matched cameras. Check seat/back proportions, tilt, frame profile and cushion layout. Reserve views that the modeler never sees.

Thresholds to calibrate
02 / Is a useful model

Valid, organized geometry

Open the saved .3dm independently. Check named parts, intended solids/surfaces, thickness and symmetry, and unwanted intersections. Agree the required editability before scoring.

Part rules to define
03 / Actually improves

Beats the starting point

Keep screenshots, evaluator and agent version fixed. Compare before and after across repeated trials and unseen cases, including cost and tool calls. Preserve earlier passing tasks.

Comparison to implement

Automatic scoring is feasible once views and rules are fixed. Screenshots alone do not reveal exact scale or all hidden surfaces. Use one known dimension, or evaluate up to a common scale; record assumptions for unseen geometry. Human judgment helps define and calibrate visual quality before routine scoring becomes automatic.
