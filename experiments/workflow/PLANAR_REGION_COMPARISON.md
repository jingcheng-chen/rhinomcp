# Prospective planar-region workflow comparison

Run only after the frozen 79-case capability trial passes and verifies restoration.
The suite is fixed before any candidate agent modeling: discovery trimmed patch,
reserved trimmed patch, and the existing through-hole solid task. Each task gets two
fresh baseline and two fresh candidate sessions in AB/BA order, using the same model
alias, effort, 24-call allowance and 240-second session limit.

Only the declared create_planar_region tool is added to the candidate's native
catalog. All original definitions must match. Freeze both binary identities and
Python sources. Restore the trusted baseline before judging hash-pinned saved models.
Document units, tolerance and layer setup must match across restarted sessions.

Require candidate correctness on every repeat and no regression on any task before
considering call reductions. Report all failures, calls, failed calls, time and token
observations. A baseline failure repaired by the candidate is a correctness benefit;
failed fast is not an efficiency benefit. Missing or changed evidence blocks a result.

The reserved patch has not been used by a modeling agent. It belongs to the same
planar family, so passing it is reserved-case evidence, not unseen-family transfer.
The through-hole task checks another modeling family's preservation; it has historical
uses and is not a globally unseen benchmark. A successful result can support a scoped
planar-region improvement, not a claim that every MCP workflow improves.
