## Cycle 1: attribute update compatibility and preservation

The [fresh planner](m3-cycle1-proposal.json) investigated 15 update failures across
three discovery families. Loaded reflection found JToken exposes
`ToString(Formatting, JsonConverter[])` but not `ToString(Formatting)`, which the
handler references. A fresh bounded builder changed that call; preflight rejected
that first candidate because direct user-data updates then lost existing/new
strings. A controller control reproduced loss using live attributes and preservation
using a detached duplicate. A fresh builder revision confines both repairs to
`ObjectAttributes.cs`. No input/output schema or dependency change is involved.

The first build/probe remains in `repair-20260910-084145-b8aad755` and
`attribute-probe-20260910-084746`. Its apparent RGB failure was observer byte-array
serialization, corrected to integer channels without changing expected colors.
The revised builder is `repair-20260910-085059-a4317332`; all 14 independent
attribute probes pass in `attribute-probe-20260910-085309`, with saved geometry and
identity preserved. The unchanged baseline rejects all eight valid update cases
with the missing-method error. Its negative-input cases merely reject calls and
are not proof of correct validation routing. See [probe evidence](m3-attribute-probes.json)
and [the exact patch](m3-cycle1-candidate.patch).

A preflight binary copy completed while the previous Rhino process was still
shutting down; no probe or agent ran in that process afterward. The revised
candidate was verified in a new process before any result was used. Comparison
transitions explicitly wait for the old PID to exit before copying and require
new-process identity acknowledgement.

The [reviewed trial](M3_CYCLE1_REVIEW.md) freezes two AB/BA pairs across small
assemblies, recovery and held-out planar curve editing. The shared pilot uses the
full 70-definition production catalog, gpt-5.6-terra medium, 50 calls and 240 seconds.
The curve task has seven calibrated saved-file fixtures, all matching expected
verdicts; no held-out geometry was supplied to the builder. Rectangular closed
curves extend the existing scene evaluator; no new orchestration was forked.

Comparison directory: `workflow-binary-20260910-085542-7d89feb3`.
**Decision: keep.** All twelve saved models pass independent evaluation on the
restored released plugin. Candidate success is 6/6, including both held-out cases;
there is no per-family correctness regression or failed-call increase. The full
catalog lets baseline agents recover through scripts; the improvement is lower
friction with identical final task correctness.

## Instrument correction

M2's original audit missed three bare `{"error": ...}` results from get_object_info.
The corrected classifier counts those failures while preserving ordinary object
data containing an error field. Raw traces and saved-file verdicts are unchanged.
[Re-audited discovery](m3-discovery-audit.json): 104 calls, 19 failures instead of 16.
The correction precedes the frozen comparison and has a regression test. Original
M2 artifacts remain historical snapshots.

Two missed failures used `object_name`, which the get_object_info description
advertises despite its schema/implementation accepting `name`. This is a separate
candidate investigation after the attribute cycle, not part of its patch.

During cycle 1 transition 3, the completed first recovery baseline left a modeless
Select Name window open after its macro calls. The supervisor closed that window
only after the candidate file and cleanup were finished, before restarting Rhino.
This did not repair or re-evaluate the saved output. It is additional observed
macro friction and another reason these runs remain supervised.

## Cycle 2: object lookup selector description

The [fresh planner](m3-cycle2-proposal.json) investigated the separate misleading
get_object_info selector wording. Bounded builder `repair-20260910-092552-3c39fc7d`
changed only its docstring. [Independent source review](m3-cycle2-source-validation.json)
confirms unchanged executable AST and all 70 definitions unchanged except that
one description. All 285 server tests pass against the candidate source.

A checkout-preparation attempt stopped before builder dispatch when a transient
Git maintenance lock changed during inventory. A fresh preparation disabled Git
auto-maintenance for that process; neither a builder nor a modeler attempt was replayed.
Comparison preparation also refused the used empty document's modified flag before
any modeler dispatch. It was replaced with a fresh dedicated document. Both setup
failures remain in local evidence and do not contribute task outcomes.

The shared comparator now supports explicitly reviewed description-only source
arms on an identical binary with full catalogs. It rejects undeclared description
or schema drift and pins both source trees. Candidate Python servers are separate
fresh processes; no production source is replaced. Eight saved section controls,
including a wrong section height, all match expected verdicts and preserve the
active document. See [calibration](m3-section-calibration.json) and the
[predeclared review](M3_CYCLE2_REVIEW.md).

**Decision: keep.** The comparison `workflow-binary-20260910-093344-5aa4136d`
finished with all twelve saved outputs passing and all document fingerprints
preserved. The candidate passes both held-out cases, has no per-family correctness
regression or failed-call increase, and reduces median calls in both discovery
families under the fixed rule.

| Family | Median calls: baseline → candidate | Failed calls: baseline → candidate |
| --- | --- | --- |
| Document inspection | 4.5 → 3.5 | 0 → 0 |
| Editing existing geometry | 12 → 11.5 | 1 → 1 |

See [portable comparison](m3-cycle2-results.json) and [all twelve runs](m3-cycle2-runs.json).
The original wrong-field error did not recur in either arm. This is a wording
